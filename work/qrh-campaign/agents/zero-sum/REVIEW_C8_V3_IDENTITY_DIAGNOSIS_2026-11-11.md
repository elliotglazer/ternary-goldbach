## Minimal identity design

The proposed self-identification at an existing blocked handshake is useful. A self PID names the process executing the logging call. Comparing it with a PID queried through the still-owned original creation handle can distinguish that interpreter process from a different process returned by creation. Under the frozen benign-source and nonce-binding assumptions, a mismatch is positive evidence of different process instances; a match does not exclude a helper. [GetCurrentProcessId](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getcurrentprocessid), [GetProcessId](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getprocessid).

The future schema should make the existing identity requirement concrete: retain successful self and observer creation-time queries, original creation PID, handle-derived PID, nonce, source hash and stage. Compare creation-time values as well as PIDs when correlating reopened instances. Raw numeric handle values are process-local diagnostics, not identities to compare across different processes. `GetProcessTimes` supplies creation time; its exit-time field is not meaningful for a process that has not exited. [GetProcessTimes](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getprocesstimes).

`GetModuleFileNameW(NULL,...)` retrieves the current executable path. Require a nonzero returned length strictly below the allocated character capacity; a full buffer can indicate truncation. `QueryFullProcessImageNameW` can query the observed process through its retained query-capable handle. Preserve its success flag, path-format selection, lengths and bounded buffer. Different path spellings need not mean different files, and an equal path is not proof of loaded binary identity. The author's continued source/executable hash requirements are necessary and should not be replaced by string equality. [Current executable path](https://learn.microsoft.com/en-us/windows/win32/api/libloaderapi/nf-libloaderapi-getmodulefilenamew), [Handle-based image query](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-queryfullprocessimagenamew).

For a bounded job list, acceptance of completeness at that particular query requires successful return, a complete buffer and matching assigned/returned counts, not just the returned prefix. Nested lists include child jobs. If a larger buffer would exceed the fixed bound, retain the partial observation as incomplete. The handshake stabilizes the intended script's stage; it does not freeze every helper or make successive accounting/list queries atomic. A process can appear or disappear between them. [Job PID list](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_process_id_list).

Opened PID handles must be associated with the explicitly owned job through a successful membership query; testing with a null job only asks whether the process belongs to any job. Recheck instance identity through that handle and retain it while drawing conclusions. A failed open, a changed instance or a missing short-lived process must remain unresolved. These are implementation details of the author's stated reuse guard, not additional evidence supplied by this review. [IsProcessInJob](https://learn.microsoft.com/en-us/windows/win32/api/jobapi/nf-jobapi-isprocessinjob).

## Optional completion-port evidence

The paper correctly limits this option to positive evidence. Microsoft recommends association while the job is inactive, explicitly warns that process notifications are not guaranteed, sends nested-job notifications to ancestor ports and warns that reported PIDs may already be recycled. A separate receiving-job key identifies delivery context, not a new process instance. A confirmed extra retained instance is useful; an empty queue or equal notification count is not proof that no helper existed. The guarantee for notification-limit messages does not extend to the process events at issue. [Completion-port association and messages](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_associate_completion_port).

Information class 7 is correct for association. Polling from the existing thread does not inherently require another process or thread, but implementation would need fixed caps for messages, retained handles, bytes and elapsed work. A zero-time dequeue can time out immediately; if no packet was dequeued, the returned key and byte fields must not be treated as valid data. Preserve failure versus timeout and decode job PID payloads as values rather than dereferencing them as ordinary OVERLAPPED pointers. [SetInformationJobObject](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-setinformationjobobject), [GetQueuedCompletionStatus](https://learn.microsoft.com/en-us/windows/win32/api/ioapiset/nf-ioapiset-getqueuedcompletionstatus).

## Resulting next step and limits

Self-identity plus synchronized, bounded PID snapshots is a smaller and better-targeted next design than immediately adding completion ports. Its acceptance contract must preserve positive identity observations and inconclusive outcomes separately. It can resolve whether an original creation handle and script logger name different instances, or identify an additional still-associated instance. It is not guaranteed to explain a short-lived association or the complete lifetime counter.

V3 remains FAIL; V2 counters remain unknown. No predicate relaxation, V4 implementation, retry, numerical execution, full host-capability result or formal proof follows from this review. A versioned implementation and its exact bounds would require separate source review and authorization.
