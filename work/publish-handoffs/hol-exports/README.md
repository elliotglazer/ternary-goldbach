# Archived HOL4 theory exports

The milestone source scripts and build logs are retained with their projects. The serialized theorem data for these milestones resided under `.hol/objs`, which the publication excludes. `selected-theories.zip` preserves 52 selected exports and three available local parents: `Sector`, `LargeTerminal`, and the locally built `integral`. The bundle includes 165 files totalling 53,257,724 bytes before compression. The ZIP occupies 3,061,041 bytes and has SHA-256 `e1e1fe92a8553c85c6ca0b67e101509976d7ebff217860d93c0ce84017dbe838`.

Each theory has its `.dat`, generated `.sig`, and generated `.sml` loader. The [manifest](manifest.json) records each file's SHA-256, the source script's digest and path, and the parent names referenced by its generated loader. Preserve the directory structure in the ZIP. It distinguishes similarly named sources and associates every export with its original project. The bundle contains no compiler, runtime, heap, compiled ML object, or WSL distribution.

The archive covers the finite-height packet and Turing arithmetic, local-root parity and coverage, guard choice and height rounding, endpoint panels, compact radii and spectral-node receipts, Bernoulli and periodic bounds, q10004 and q265800 receipts, the 270-row acceptance and batch sign results, and selected projection theorems. The interrupted `ComplexTail` and `StripShift` drafts have no successful local export in their project caches. Their source files remain the record of that work.

## Inspecting and restoring

1. Check the ZIP against the SHA-256 above. Extract it into a scratch directory. Each `.dat` is a serialized HOL theory object. Open its adjacent `.sig` to see the exposed ML declarations and its `.sml` to see the exact internal theory hash and lookup names. The internal HOL hash and the SHA-256 used for archive transport serve different purposes.
2. For ML access, use the HOL4 revision `1de64f8521b4758508bd875fbaf11d1768261b92`, a compatible kernel/runtime and the theory's parents, including the project-specific parents listed in its generated loader. In a compatible existing build, restore the matching three files to the project's `.hol/objs` and load the theory normally with its existing matching ML loader metadata. For example, a restored `RoundedHeightTheory` makes `RoundedHeightTheory.closed_height_restrict` available to ML. A clean environment must first provide the parent's build and loader metadata. The original project source, Holmakefile, inputs and build recipe remain the reproducible route for that environment.
3. To inspect serialized data through the pinned reader in an initialized matching HOL session, use the `TheoryReader.load_thydata` call shown in the generated `.sml`, supplying the extracted `.dat` path and the exact `thyname` and `hash` from that file. The loader then retrieves the named theorems with `Symtab.lookup`. The extracted files alone do not supply the dependency environment.

The [archiving script](archive.py) copies existing outputs and verifies every ZIP member against the recorded bytes. It was run on the original workspace. The archive was verified by rereading all 165 members. No prover, proof replay, or clean-environment loading test was run during archiving.
