# Historical computational evidence: what can presently be reused

Bounded public-source inspection, 2026-11-12 local / 2026-11-13 UTC. **Code and useful numerical data survive publicly, but this inspection did not locate a complete, independently replayable archive of all sign enclosures and completeness calculations for Platt's full 2013 Dirichlet-GRH computation.** This is a finding about the inspected public material, not a claim that no private or unindexed backup exists.

Existing local research was checked first: `forecast-audit-20261113/PRINCIPAL_COMPLETENESS.md` already explains why historical zero locations can guide discovery without replacing sign/count proofs. Its historical CPU figures concern performed computations, not availability of their outputs. No such figure is used below as evidence that a certificate archive survives. No one was contacted, no code was compiled or run, no large dataset was downloaded, and no existing campaign artifact was changed. One public 24-KiB statistics file was read in memory.

## Availability ledger

| Item | Public material actually established | What is not established |
|---|---|---|
| Platt Dirichlet-GRH implementation | Public source files for interval samples, Fourier methods, upsampling and Turing/count checks in `djplatt/code`; selected source contents inspected | A frozen release/manifest identifying exactly the final 2013 executable, parameters, inputs and every successful output |
| Full 2013 Dirichlet-GRH evidence | Programs capable of writing interval sample arrays and unresolved-case state | Complete surviving arrays for every required character/height, all repaired cases, and replayable Turing arithmetic |
| Platt/LMFDB Riemann-zeta data | Documented complete ordinate dataset through 30,610,046,000; public decoder with block endpoints and zero counts | A sign-value/interval and Turing-calculation transcript inside that ordinate format |
| LMFDB Dirichlet L-functions | Public individual objects and an explicit database coverage statement | Coverage of all conductors/heights of Platt's much larger GRH computation, or a certificate export proving those claims |
| Original binary Goldbach computation | Author's statistics tables, status grid and proof-of-concept sieve source links | Full per-even Goldbach witnesses, full production assembly source release, or a formally replayable full-range certificate |
| Helfgott–Platt prime ladder | Paper algorithm, public source candidates, and explicit paper account of witness-file deletion | A retained complete ladder certificate ready to ingest |

## Platt code: real source availability, incomplete run provenance

The public [djplatt/code repository](https://github.com/djplatt/code) was accessible. GitHub's API resolved `master` to **`1f19fcbefa33d2fe5949ddbcd4d3df75deca6819`**; its recursive tree listed 3,760 entries with `truncated=false`. This is a current repository snapshot, not a claimed historical release. Relevant directories include `low_q`, `low_q_mpfi`, `l-func`, `l-func-fourier`, `zeros`, `int_double`, `includes` and `proth`. The top-level page supplies no project description. Directory names alone were not accepted as a proof of purpose or completeness.

Two inspected source files give stronger evidence:

- [`low_q/f_even1.3.cpp`](https://github.com/djplatt/code/blob/1f19fcbefa33d2fe5949ddbcd4d3df75deca6819/low_q/f_even1.3.cpp#L167-L184) writes modulus/index information, a complex `omega`, parity/reality flags, a sample count and an array of `int_double` real samples. It therefore documents a potentially reusable interval-sample output format. Availability of the producer **does not show that the produced files remain available**.
- [`low_q/low_upsam8.cpp`](https://github.com/djplatt/code/blob/1f19fcbefa33d2fe5949ddbcd4d3df75deca6819/low_q/low_upsam8.cpp#L110-L188) moves an uncertain Turing start, calls real/complex zero-count routines, compares with detected zeros, writes state on failure or missing zeros, and prints success on completion. This distinguishes a native checking pipeline from an archive of every accepted sign/count calculation. The file is dated February 2010; no claim is made that this exact version was the final 2013 production checker.

The [`make_me.sh`](https://github.com/djplatt/code/blob/1f19fcbefa33d2fe5949ddbcd4d3df75deca6819/low_q/make_me.sh) file contains compiler commands using rounding-sensitive flags and CRlibm. Numerous numbered/experimental versions coexist. The inspected repository listing contains some numerical and test files, but no inspected manifest establishes full 2013 run coverage. This inspection did not classify every binary blob, recover old releases, or audit the programs' numerical correctness. These are code-recovery leads, not turnkey certificates.

Platt's [2013 paper](https://arxiv.org/pdf/1305.3087) describes interval arithmetic and the sign/count strategy. Its theorem and methodology do not by themselves identify an output archive. The author's [dataset page](https://people.maths.bris.ac.uk/~madjp/Datasets/Datasets.html), read as raw HTML, currently links a Selberg-zeta dataset; it did not expose the full Dirichlet-GRH output collection in this inspection.

## Zeta ordinates: stronger data availability, different evidence layer

The [LMFDB completeness page](https://www.lmfdb.org/zeros/zeta/Completeness) states that its dataset consists of the 103,800,788,359 zeta zeros with positive ordinate at most 30,610,046,000, all on the critical line. Its [source page](https://www.lmfdb.org/zeros/zeta/Source) credits Platt, specifies absolute ordinate precision ±2^-102 and says completeness was established by rigorous Turing verification. These are explicit producer/database provenance assertions; this task did not independently re-establish them.

The public [decoder](https://github.com/LMFDB/lmfdb/blob/master/lmfdb/zeros/zeta/platt_zeros.py) was inspected. It reads a block count; block headers contain `t0,t1,Nt0,Nt1`; subsequent compressed integers reconstruct ordinate differences at scale 2^-101. It reads no completed-function sample enclosures or arithmetic proof of the stored `N` values. Thus the format contains **zero locations and count metadata**, not merely unlabeled decimals, but the count metadata is still not a replay of Turing's method. The decoder even documents a trailing-data caveat for at least one file, reinforcing the need for exact format/index checks.

The source page links [raw downloads](https://beta.lmfdb.org/data/riemann-zeta-zeros/), and the main page links [another bulk URL](https://beta.lmfdb.org/riemann-zeta-zeros/). The web reader returned 403; a direct small request returned an HTML JavaScript/cookie gate rather than a file index. No bulk file or index was fetched. Therefore this review verified the advertised dataset, metadata and decoder, **not present byte-by-byte availability of every raw shard**.

For the later zeta verification to about 3×10^12, [Platt–Trudgian §2](https://arxiv.org/pdf/2004.09765) explicitly distinguishes that computation from the high-precision database: it avoided refining each zero beyond what was needed to count it and states that storing that many zeros was impractical. One must not silently extrapolate the LMFDB archive to that later height.

For Dirichlet L-functions, [LMFDB's current coverage page](https://www.lmfdb.org/L/Completeness) lists 7,655,469 primitive-character functions, including all conductors at most 2,800. An [individual source page](https://www.lmfdb.org/L/1/4161/4161.1367/r1/0/0/Source) credits Platt's thesis algorithms. Neither statement supplies the full modulus/height coverage of the 2013 verification or a full sign/Turing receipt export. Zeta and general Dirichlet archives must be budgeted separately.

A separate useful lead is [Bennett–Martin–O'Bryant–Rechnitzer, §6](https://personal.math.ubc.ca/~bennett/BeMaObRe-MathComp-2021.pdf): it reports storing rigorous zeros for primitive conductors at most 934 in its stated height range, with generator/processing code advertised at `http://www.nt.math.ubc.ca/BeMaObRe2/`. The advertised endpoint was inaccessible/404 in this check. This is a smaller, independent computation, not evidence that Platt's full archive survives. No current contents or complete sign transcript were verified there.

## Binary Goldbach and the prime ladder

The [original Goldbach project page](https://sweet.ua.pt/tos/goldbach.html) records per-interval statistics, minimal-partition first occurrences, prime-gap statistics, status and cross-check information. Its linked [`goldbach/t0.txt.gz`](https://sweet.ua.pt/tos/goldbach/t0.txt.gz) was successfully read in memory: 24,812 compressed bytes. The header identifies the tested interval `[4,4d18]` and double-tested interval `[4,4d17]`, then describes `S(p)`, not one partition witness for every even integer. The site also links [`gaps/t0.txt.gz`](https://sweet.ua.pt/tos/gaps/t0.txt.gz) and related tables; those were not downloaded here. This supports reuse of statistics and regression cases, not full finite theorem replay from the table alone.

The author's [sieve software page](https://sweet.ua.pt/tos/software/prime_sieve.html) explicitly labels the linked [`prime_sieve.tgz`](https://sweet.ua.pt/tos/software/prime_sieve.tgz) and [`fast_sieve.tgz`](https://sweet.ua.pt/tos/software/fast_sieve.tgz) as proof-of-concept implementations. It distinguishes the faster production mod-30/assembly implementation. Links and descriptions were checked; the archives were not downloaded. I did not verify a public release of the entire original production verifier or a full-range witness archive. This is unknown availability, not evidence of deletion.

The prime ladder is different. [Helfgott–Platt §4](https://arxiv.org/pdf/1305.3062) says the Proth `k,a` values were written, checked using an independent library, and then the per-range data file was deleted. General-prime cases were checked separately. That explicit deletion statement applies to those ladder witness files, **not to the binary Goldbach or GRH outputs**. The public [`proth` directory](https://github.com/djplatt/code/tree/1f19fcbefa33d2fe5949ddbcd4d3df75deca6819/proth) includes `check_proth.c`, `check_proth.cpp`, `harald.c` and numbered producers; directory metadata was inspected, not their full correctness or exact production provenance. Helfgott's [February 2026 public messages](https://leanprover-community.github.io/archive/stream/423402-PrimeNumberTheorem%2B/topic/New.20subproject.3A.20Odd.20goldbach.20for.20small.20n.html) separately report finding his code and not retaining the list. This corroborates a code-versus-witness distinction, without proving that every possible backup is absent.

## Practical consequence for the full-cost study

There is a defensible **reuse opportunity**: recover and pin the historical implementations; use published zero locations or sample arrays, if obtainable, to choose promising sign-test points and diagnose exceptional cases; use existing Goldbach statistics for consistency checks. None of that requires treating archive assertions as new axioms.

There is not yet a defensible **zero-regeneration-cost assumption**. Before counting a historical GRH archive as a ready certificate, require an actual manifest binding every character, height, endpoint, sign enclosure, exceptional repair and completeness calculation to the decoder and analytic error contracts. No inspected archive met that requirement. The ordinate database can reduce discovery work, but a standard-axioms proof still needs justified sign evaluations/counting evidence or another independently checked route. Binary Goldbach likewise needs proved coverage witnesses or a replayed verified computation, not only aggregate totals. For the deleted ladder files, regeneration is the default planning assumption unless a concrete surviving replacement is produced.

These findings neither prove the historical computations wrong nor establish that regeneration must repeat their original wall time. They identify what is publicly evidenced now and prevent an unverified archive assumption from disappearing from the cost model.
