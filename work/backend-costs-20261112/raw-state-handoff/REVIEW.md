## Identical output contract and full producer

Both treatments are designed to export the same empty-hypothesis theorem after unfolding their private input names:

`raw_pipeline [1;2;3;41;61;10004;262144;265800] 61 128 sources = SOME heads`.

Here `sources` is the identical literal list of eight initial/step pairs and `heads` is the identical literal four-row, 129-pair output. The generator's final checks require exact HOL term equality with that proposition; the separate cross-import program requires `aconv` of the two final conclusions and empty hypotheses. The output is all 516 pairs, not a hash or summary.

The materialized path checks `raw_produce`, decodes all 1,032 state pairs, compares the result with the proposed literal, defines and translates that literal, checks the consumer and composes `raw_pipeline_join`. `TRANS producer_th (SYM trace_def)` has the correct direction: producer equals the named materialized trace. The join's five conjuncts match the base list, conductor, depth, producer equality and consumer equality. The final source-definition rewrite removes the treatment-specific name from the public theorem.

The fused path evaluates the pipeline directly without first constructing or translating the intermediate HOL trace literal. Both paths still construct the same final literal and check exact equality. Control data occur in generated wrapper code but their HOL construction/evaluation occurs only after the primary-complete marker. Fresh processes avoid reusing the materialized treatment's representation cache in the fused treatment.

`raw_shape` checks exactly eight rows, each of length129, and the strict coordinate bound `-2^121 < coordinate < 2^121` for every state. Successful consumption must therefore traverse the three unused output-source rows too; they cannot simply be omitted from the fused producer. `raw_trace` retains index zero and performs exactly128 updates to return129 entries. `raw_heads` truncates unequal lists as a total function, but the successful shape guard excludes that ambiguity for this experiment. Denominator row4 is base61 and numerator rows0–3 are bases1,2,3,41 in the pinned fixture. The base-list guard alone does not prove analytic semantics of supplied seed pairs; that obligation remains outside this integer contract.

## Exact arithmetic and trust boundary

Three fixed integer checks verified the source constants are exactly `2^122`, `2^140` and `2^121`. The recurrence uses four signed products, combines real/imaginary numerators, and rounds once per coordinate using the existing `round_scaled s r = (2*r+s)/(2*s)`. Its positive denominators give the same nearest/ties-toward-positive-infinity convention as the Lean fixture. `BlockRound.round_scaled_residual` is the ordinary HOL proof of the signed residual interval.

The consumer's numerators are exactly `61*(ur*vr+ui*vi)` and `61*(ur*vi-ui*vr)`: conductor times conjugated denominator state times numerator state. Grid120 times grid120 followed by division by `2^140` gives grid100. No complex division or sign reversal is hidden here. A dedicated HOL complex-denotation/raw-head error theorem is not exported by these files. The source pattern agrees algebraically with the paper, but integer output equality must not be relabeled a full raw-head analytic certificate or analytic port.

The preparation script computes only untrusted proposals. Its Python recurrence checks and expected heads do not establish HOL truth. Acceptance instead comes from translated definitions, representation/from-to theorems, ordinary `cv_compute` conversion, decoding and proof composition. The instrumented `evaluate` follows the inspected `cv_eval` proof-producing route; it closes preconditions, checks empty hypotheses and checks that the equality's left side remains the requested term. No native array is installed as a theorem by an unchecked constructor in the reviewed source.

The runtime inspects ancestor axioms against the declared standard HOL whitelist and permits only the existing `DISK_THM` import tag, rejecting other theorem oracle tags. This permits the established imported-theory trust boundary; it is not independent rechecking of all imported proofs. Concrete logs must still show the expected context/tag checks and successful closure. Final compiled evidence, rather than this paper read, must establish that all precondition tactics and HOL APIs work as written.

## Controls and evidence requirements

Controls follow primary acceptance. They check changed seed/step, interior trace entry, swapped rows, dropped/repeated row length, changed final entry, wrong base label and wrong denominator; positive and negative half ties are checked too. Interior/row controls compare the full producer trace, while length controls test the shape predicate. They must all produce the expected false/true theorem results, not merely fail by timeout or syntax error. These bounded controls are useful but are not a universal mutation-completeness proof.

The shell runner uses sequential phases, a600-second timeout per phase, a4GiB virtual-memory limit, exclusive labels and `--no_prereqs`. Existing prerequisites remain imported. A missing dependency stops the experiment rather than licensing a rebuild. A completed generic build may be a cached no-op on subsequent attempts: retain which artifacts existed at launch and do not report it as first generic-theory construction. A fresh label preserves logs, not automatically fresh compilation or cold OS caches.

The final receipt should bind the fixture, preparation source, emitted wrappers, generic/runtime source, prerequisite versions and executed artifacts to the actual run. The preparation receipt records generated-wrapper hashes, but the current runner/summarizer do not independently compare those stored hashes to before/after executable provenance. Coordinator pinning can supply this missing evidence without changing the mathematics. The summarizer's success markers and exit-status checks are useful consistency checks, not a substitute for inspecting the complete successful logs and exact final theorem.

## Cost interpretation

The source exposes source-literal construction/definition/translation, final-literal construction, representation proof, from/to lookup, equation/conversion setup, checked computation, decoding, precondition closure, binding and theorem save. The materialized treatment additionally pays intermediate decoding/literal construction/definition/translation and proof composition. The fused treatment still pays producer computation. This is a deliberately explicit materialization baseline, not a claim that all HOL callers use that baseline or that a representation-theorem cache cannot improve it.

The sum of primary instrumented phases omits small uninstrumented gaps such as term construction, tag checks and marker/printing bookkeeping. Call it exactly that sum, not total first acceptance. Whole-process CPU includes these gaps, startup/imports and later controls/export. Build CPU and proposal-generation CPU are separate. Never add primary phase CPU to whole-process CPU. Internal phase timers and process CPU also have different boundaries; inspection of eventual receipts must retain them separately.

The exported theory contains controls as well as the final theorem, so export time and bytes are full-context observations, not pure primary-result costs. The two treatments can accumulate different local proof/definition contexts; that is part of this implementation's measured export cost, not a free representation saving. The experiment presently has one run per treatment; it cannot establish a robust distribution or remove order/cache effects.

This sample can answer whether this checked integer boundary is cheaper when fused. It cannot replace the full forecast's representation row: actual spectral partitions, fresh/reloaded payload counts, shared coefficient lifetimes, analytic source ports, sign/completeness success and full implementation costs remain unmeasured. No ratio, runtime forecast or adoption is authorized by this preflight.
