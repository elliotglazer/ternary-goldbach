# Evidence required for a HOL4 comparison with Platt

Prepared 2026-11-12 from the pinned local evidence below. This is a research acceptance plan, not a new forecast, theorem anchor or implementation approval. No build, evaluator, workload inventory or benchmark was run.

## Present evidence and numerical target

The existing HOL planning scenario is 522.5677489460336 core-years. Removing only its finite coverage/ladder row, 26.270919793964055 core-years, leaves **4,350,538 core-hours**, including the model's shared reserves. These are conditional model values, not measurements of the selected spectral workload. One model core-year is 8,766 hours.

The literal-representation row alone is 1,994,587 core-hours. Even deleting it completely leaves about **2,355,951 nonfinite core-hours**. No experiment presently justifies that deletion. Improving intermediate data handling alone cannot establish the requested historical-scale comparison.

The proposed **20,000 representation + 200,000 arithmetic + 180,000 other = 400,000 core-hours** is an engineering allocation. It is not a measured decomposition, probability interval or permission to fit transfer factors. It targets the approximate historical full-run scale, not the smaller 160,000-hour figure. A separate 160,000-hour claim needs its own measured total and matching historical subset definition; satisfying the three allocations above would not establish it.

`PRINCIPAL_COMPLETENESS.md` attributes about 400,000 native core-hours to Platt's 2013 computation of 29,565,923,837 primitive L-functions through modulus 400,000. The current selected domain, heights, guard schedules, principal obligation and formal acceptance work differ. The parent-supplied historical 160,000-hour used-subset comparison is a second reference point. This audit has not located a timed, exact subset-to-current-domain mapping and therefore does not treat 160,000 as a measured cost for the present task. A ratio of character counts or height-volume metadata cannot supply that mapping.

## Fix the comparison boundary first

Publish both totals below rather than silently changing the meaning of “Platt's hours.”

1. **Comparable numerical campaign:** actual source/coefficient production, all numerical discovery and retries, first formal acceptance, sign repair and complete counting for a precisely named conductor/height domain, including required shared setup and export. State which principal work is included in each historical and proposed total.
2. **Full selected nonfinite formal task:** the first total plus all remaining analytic-library construction/checking, source/decoder bindings, theorem assembly, process/cache management and shared reserves actually assigned to this task. List finite binary/ladder work separately. A reserve is an unresolved cost, not proof that its obligation is closed.

Measure generation plus first acceptance once. When a proved evaluator internally produces its own values, do not add a second hypothetical external generation pass. When external proposals are used, include their production and failed proposals. A second independent replay is a separate optional line. Warm repeated checks with imported generic theory are not first construction, even if the concrete theorem is renamed and rechecked. Report both cold setup and warm throughput with the actual legal cache lifetime.

Record process CPU, child-process CPU, elapsed time, peak memory, bytes read/written and machine configuration separately. Parallel wall time is constrained by available cores, critical paths and bandwidth; it is not the CPU sum. Historical and current processor-hours are not interchangeable performance units. A same-algorithm native reference on current hardware can help calibrate hardware and formal overhead, but must use the same inputs, precision, success criterion and error contract. No universal HOL/native multiplier follows.

Human porting effort and calendar risk remain separate from measured library build CPU. Library build costs require an implemented dependency set and reproducible clean/incremental protocols. Do not replace missing mathematics with extra CPU hours or infer that a successful arithmetic evaluator ports the analytic library.

After these entry blocks, broaden only the dimensions that have demonstrated different costs: plan class, actual operand width, source band, cache state, precision, character type and repair regime. A few convenient conductors cannot justify a family-wide error bar. To claim campaign confidence, either establish conservative bounds for uncovered strata or measure a prespecified sampling scheme with valid treatment of its tails. Persistent unresolved cases block a completion claim regardless of average speed.

## Cost gates and decision rules

Use a single ownership ledger. Representation includes decoding, term construction, input/consumer binding, cache loading, serialization and final output. Arithmetic includes the admitted numerical circuit and its arithmetic acceptance. Other includes source/elementary work not assigned to arithmetic, principal/count/repair work, imports/scheduling and library costs. Each operation belongs exactly once; split mixed measurements before comparing the 20k/200k/180k targets.

For measured stratum j, record its actual count n_j and complete warm cost w_j. For cache class k, record cold cost s_k and observed or guaranteed reload count r_k. A supported aggregate has the form

```
T = sum_j n_j*w_j + sum_k r_k*s_k
    + actual failed work + export/transport + shared library/setup.
```

All counts must describe the same selected version and successful completion protocol. The current model's notional block reuse100, type/width factors, off-grid fractions, refinement multipliers and closure seconds per label are assumptions to replace, not calibration constraints. Unknown rows remain unknown. Keep a central estimate and a justified conservative envelope distinct; a stress scenario made from arbitrary factors is not a proved upper bound.

For a fused producer/consumer alternative, let S be extra cold setup and let d be the measured reduction in complete per-use cost after including new source proof, binding and export. Adoption is justified over q legal uses only if **q*d>S**, with q supported by the actual memory/cache schedule. A negative d or eviction before break-even rejects that implementation for that stratum. This is the immediate useful test for the representation allocation.

A claim of “roughly 400,000 hours” becomes supportable only when the declared comparison domain and cost boundary are fixed, complete block measurements cover or bound every material stratum, repair/count termination is supported, and their independently checked sum with remaining uncertainty fits the explicitly stated tolerance around400,000. State that tolerance before assessing the result. The same rule applies independently to160,000. If measured costs exceed an allocation, revise the algorithm or the target; do not shrink an assumed factor until the sum fits. Success on representation while arithmetic or completeness is unmeasured is partial progress, not historical-scale evidence.

The finite HOL result already illustrates this discipline: a roughly138-fold improvement in isolated primality checking produced only about1.40-fold improvement in the complete process. Consequently the next decision should be based on one complete low-height large block and its source/cache costs, then the missing Blue/small/high/count classes. It should not be based on another isolated multiply rate.
