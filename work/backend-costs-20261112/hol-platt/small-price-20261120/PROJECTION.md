# Primitive projection before the long transform

The c=10000 pilot fixes the group C2 × C4 × C500 and 68,268 nonnegative frequencies. At each frequency, apply the C4 transform first. For each fixed C2 and C500 input index and each odd output j=1,3, the four-term sum equals (x0−x2)+i^j(x1−x3) under the positive sign convention. Thus one can discard both even j branches before executing any length-500 transforms. The C2 transform commutes with this projection. Both surviving complex outputs use exact additions, subtractions and a quarter turn. For a fixed fully populated separable reference that runs the length-500 axis on all eight slices, this saves four entire length-500 transforms per frequency, or 273,072 across the conductor. This is a comparison with that specific dense ordering. It gives no saving against an implementation already restricted to primitive slices. Sparse parity-specific layouts need their own count. The half-length Hermitian time transform discussed in SPECTRAL_STRATEGY.md addresses a different axis.

## Audit of the charged schedule

The producer small_family_minimal_theta_20261111.py sums v/d complete slices per axis and charges h times R copies of that tensor. The c=10000 saving above is per parity input. Counting both separate parity inputs saves 546,144 length-500 transforms. The released ledger uses 1024-point Bluestein convolutions for those transforms. Its bootstrap phase and Gaussian setup have separate prices.

fold.py reproduces both main character ledger totals from the 7,499 saved rows. For odd prime powers p^e the primitive local label count is p-2 when e=1 and (p-1)^2 p^(e-2) otherwise. For 4 retain the sole nontrivial character. For 2^e with e>=3 both C2 signs survive and precisely the odd cyclic labels survive. After each whole axis transform discard outputs with imprimitive local labels before the next axis. Complete retained slices use the same roots, rounding grids, order within each slice and scalar normalization. Under fixed coordinatewise rounding with no global dynamic rescaling, this deletes only operations outside retained outputs' dependencies. The earlier C4 shortcut is unnecessary for these savings. Both parity sources still traverse their own scheduled slices.

In factor-list order the main ledger falls from 128,941,391,789,290 to 95,864,578,358,990 butterflies and from 25,399,177,848,072 to 18,394,224,556,512 point products. Minimizing butterflies over axis permutations yields 95,508,733,534,910 and 18,339,179,561,968 respectively. Reordering can change rounding and needs an error proof. fold.json gives cohort counts. The original price sum is permutation invariant and specifies no executable traversal. No parity-conjugacy or intra-axis pruning is credited.

slice.py uses the selected c=10000 character fractional precision, 307 bits, to run a 1024-point forward FFT leg on synthetic complex values and checks the DC output against an exact sum. The 15 runs in slice.txt use 0.140625 aggregate CPU seconds for 76,800 butterflies. The coarse Windows CPU timer, Python loop cost, synthetic input, and omission of the rest of the Bluestein circuit limit interpretation. No HOL or interval validation ran.
