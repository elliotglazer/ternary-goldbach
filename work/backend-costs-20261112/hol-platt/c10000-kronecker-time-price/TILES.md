# Bounded middle-window convolution

For fixed tile length T=65,536, every scalar integer product in the schedule has operands at most 6,094,848 bytes and output capacity at most 12,189,696 bytes before multiplication scratch. The large-conductor and small-conductor rows use the same algorithm. The cost is 1,051,852,215 scalar tile products over 7,499 conductors, with a synthetic product-only model of 86,426 CPU hours. No production conductor was run.

## Tile count and accumulation

Let the source length be L=2J+1 and the difference kernel length K=L+m. Linear source tile i of length a and kernel tile j of length b contribute exactly to indices from (i+j)T to (i+j)T+a+b−2. Count the pair precisely when this interval meets [L−1,L−1+m]. Both trailing ragged lengths use their actual sizes. Within each of the four rectangular families of full/ragged tile choices, the allowable i+j values form one integer interval. tiles.py counts these diagonal bands by triangular inclusion–exclusion. An independent explicit tile enumerator checks all 3,224 small triples of source length, output span and tile size. The two possible pieces of each product are likewise counted separately against the requested output interval.

Use the same byte-aligned radix R=2^w derived for the entire convolution. Every whole or partial coefficient of any of the three real products has magnitude ≤4LXY<R/2 by the absolute sum bound. At product split position T, the signed integer polynomial comprising the low T coefficients lies strictly between −R^T/2 and R^T/2. Thus the low part is the centered residue mod R^T, and subtracting it before the exact division yields the high part, including for negative leading coefficients. Ordinary unsigned slicing without that carry correction can fail. Add the signed low/high pieces to their two natural output tiles. The same global magnitude bound applies to every partial sum, irrespective of the accumulation order. Recovering signed digits and combining the three real convolutions yields the same exact pre-postchirp integer numerator as the untiled circuit. Boundary tiles may accumulate whole pieces and discard the unrequested coordinates only at extraction.

Process tile pairs by ascending i+j. After completing diagonal d, the output tile d has received every possible contribution from diagonals d and d−1 and can be finalized. Two adjacent accumulation tiles suffice per real multiplication family, in addition to input, product and temporary buffers. On each emitted tile recover re, im, apply the actual postchirp, divide by N and take the specified output rounding. The row-level analytic bounds from README.md therefore still apply. This is an algorithm and arithmetic proof sketch. No memory profiler has verified peak implementation RSS. Input or kernel replay traffic can increase if those large arrays are streamed or evicted. A theorem proving multiplication of the integer constants, centered splitting, indexing, and complete accumulation must still be supplied by a formal backend.

For c=4 the larger tile yields 15,736,695 contributing tile pairs per character; the three exact products per pair require up to 5,046,272 bytes per scalar operand. For c=10000 it yields eight pairs per character, five full and three ragged, with 4,456,448 bytes per full scalar operand. Both row counts include the actual requested output prefix.

The throughput model assigns each row to the next greater or equal field width among 552, 616, 680 and 744 bits. At each width and tile size it times three seeded full-operand products using one FLINT thread and the median process CPU time. It charges every ragged product as if it had two full-size operands in that class. This assumption is a proxy, not a mathematical time bound. The single-worker wall-time versions of the two sums are 193,643 and 88,160 hours respectively. Each measured result was checked modulo 65,537. These timings cover one native software and hardware configuration.

The 65,536-tile plan represents 9.404 PB in summed scalar operand capacities and another 9.404 PB in result capacities before scratch. The corresponding totals at T=16,384 are 31.965 PB each. Summed capacities do not specify memory bandwidth or proof traffic. Both alternatives retain 1,775,431,871,117 real samples, the original coefficients, certified chirps, pack/decode work,  real-part completion, signed arithmetic, final roundings, interpolation and the proof/output sink. Kernel reuse, compressed transport and threading require separate measured policies. These controls do not establish a formal checker runtime, compare it with a fully optimized FFT, or give an end-to-end campaign price.
