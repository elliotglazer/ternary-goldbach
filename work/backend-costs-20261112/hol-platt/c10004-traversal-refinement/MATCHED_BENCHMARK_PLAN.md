# Matched outer-traversal diagnostic

Prepared before observing sequential timings. This is an experiment plan, not a speed claim. It is subordinate to the full source-to-sign/count acceptance requirements in CONFIDENCE_REQUIREMENTS.md.

## Entry gate

Require accepted C10004TraversalBase and C10004TraversalRefinement builds and exact-conclusion reload audits, including the unconditional ft_checked = tx_checked theorem. Translate the actual ft_* definitions through unchanged stock HOL CV rules in a separate theory, then audit its ancestry, generated preconditions and public roots. Do not obtain theorem authority from the untrusted typed worker. The preserved C10004Transform and C10004TransformTests artifacts remain read-only.

## Matched workload

Use the existing p81 synthetic root packet and both 4800-element input fixtures identified by parameters 1 and 2. These parameters are fixture labels, not analytic heights. Every public call constructs the same root cache and performs the same root, input and output checks. The existing test_public_success predicate returns a Boolean after checking a 2301-element successful result. Define its sequential counterpart with only the public entry replaced by ft_checked.

Measure both entries in the same bounded single-CPU environment. Run both execution orders in separate processes and retain at least three warm calls per entry and fixture. Report individual CPU observations, medians by fixture and order, cold preparation, whole-process CPU, wall time, peak memory and exported sizes. Charge construction and first-admission work separately. Do not compare a new run directly with old tx08 observations as a controlled speed ratio.

Each measured call must use the same stock proof-producing evaluation boundary. Check the exact evaluated proposition, true/false result, empty hypotheses and permitted tags. Track representation preparation, evaluator execution, Boolean decoding and theorem storage separately where instrumentation can identify them; retain their complete total too. Reusing proved function translations is allowed, but replacing repeated evaluation by a previously proved closed Boolean result is not a timed execution. Record any cache retention explicitly.

## Controls and limits

Before accepting timing, check the two complete output equalities on the fixed fixtures, the impulse output, rejection of short input, an invalid exact root and an out-of-range input, and rejection of an altered output. The universal refinement remains the all-input correctness argument; sampled equalities alone do not establish it. Generic shape contracts include empty and zero-width dimensions, while the public entry retains exactly the original length and magnitude guards.

This measures only the implementation change from indexed outer lists to sequential pair/chunk/column traversal. Inner 40/60 arithmetic and root lookups remain the reference programs. It does not price actual analytic sources, roots, errors, strict signs, difficult repairs, completeness counts, Bluestein, small-family time transforms, high restarts, principal work or finite coverage. Even a large diagnostic speedup must not be applied to the full arithmetic group or the fresh-input-translation row. The frozen end-to-end forecast changes only when complete representative work supports replacement prices.

The pre-benchmark C10004_ARITHMETIC_PRICE_INTERFACE note traces24720 root products,37821 complex adds/subtracts and219 quarter turns, priced at approximately0.062634 seconds by the frozen nominal arithmetic assumptions. This is neither a full call price nor a measured target. The model already assumes production adapters, so a ratio against the slow reference cannot be credited directly as a forecast reduction.
