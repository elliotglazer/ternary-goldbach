# Independent audit of the small Goldbach extension

The predecessor covers every even natural from 4 through 10,000,000,000 inclusive. The first join adds 67,108,864 even inputs through 10,134,217,728. The second adds 536,870,912 through 11,207,959,552. The public theorem quantifies over natural n and requires Even n, 4 <= n, and n <= 11,207,959,552. Its conclusion supplies two natural primes whose sum equals n. It allows repeated primes.

Covered lo hi is half-open and tests parity by n % 2 = 0. SmallGoldbach.join requires precisely the same middle endpoint in both proof types. The public split moves after prior inclusive upper bound B to B+2 because n is even. The checkRows premise of checked_interval enforces the computed row bitmap coverage. Its final premise bounds the half-open endpoint by the sum of verified row widths.

The independent auditor reads the Lean text and receipts directly. It recomputes primality for every selected large anchor by an independent odd segmented sieve, constructs the low-prime bitmap from an ordinary Eratosthenes sieve, and checks every column in all packed rows for a prime pair. The native test neither imports the producer nor needs its inverse certificates. It verifies joins in order at every block and shard, checks both source and olean hashes against each successful receipt, and extracts explicit prime decompositions for both endpoints of each shard. A fault-injection pass advances the start of each following shard by two. The expected missing even is the exact cutoff shared by its neighbors.

## Restart semantics

The producer selects its first number and its fixed shard geometry from the milestone flag. Every row, block and shard boundary is computed afresh from that origin, independent of a mutable cursor. A matching local receipt carries both the module source hash and olean hash. Resume skips work if the stored return code and both hashes match. If a module was interrupted before a successful receipt, it recompiles. A missing olean behind a successful receipt raises on hashing instead of triggering a rebuild. A partially written JSON receipt can fail to parse. The existence of producerB.json skips regeneration on resume, and the receipts omit the generator, imported oleans, Lean executable and command hashes. A matching local pair therefore attests its earlier run; it does not attest that its dependencies, generator and flags still match the current environment. Explicit release-time import and typed-join controls cover the current public claim. The live producer was left unchanged.

## Sharing setup

The low-prime bitmap proof Power10.certifiedSource is already reused across both extensions. The per-shard checked_interval theorem also accepts a shared proof fac=d!, and multiple adjacent bands may use one d whenever each selected anchor p is below (d+1)^2. Changing d changes the modular inverses expected in each newly generated row. Old public shard theorems need only be imported. The existing 106000! covers anchors p<11,236,212,001, leaving a short margin above the current public endpoint. At the next threshold, factorial_extend derives (d+m)! from the earlier checked literal d! and a balanced product containing only the next m factors. The two timing controls verify the same packed 106000! integer using the old 101000! proof with 5,000 new factors or a full 106,000-factor product. Both import the same modules.

## Results

All six emitted shards and both public extension joins match their successful source and olean receipts. The independent sieves reconstruct prime-pair coverage for 603,979,776 new evens in 2,304 rows and 288 checked blocks. The predecessor supplies the range through 10,000,000,000. The extension ends at 11,207,959,552 inclusive. A fresh Lean 4.35 import typechecked that exact statement and reported only propext, Classical.choice and Quot.sound. The independent numeric replay covers the new portion; it does not replay the earlier ten-billion certificate.

All seven copied endpoint faults failed: the predecessor-to-first-shard transition, the five internal shard transitions and the final included even. The separate Lean negative control omitted exactly 10,402,653,186 from the right shard. Lean rejected 10,402,653,188 as the shared middle endpoint. A fresh sieve found the two primes 10,402,646,789 and 6,397 at that exact omitted even. Positive.log and SkippedEven.log record the live imports tested; lean-controls.json binds their input and output hashes.

The restart fixture uses the exact AST of the producer's skip predicate. It confirmed unchanged source and object were skipped even after its simulated dependency changed, changed local source or object were rejected, and a missing previously successful object raised FileNotFoundError. No fault was applied to the live run. See restart-controls.json.
## Incremental factorial result

Lean proved the generic factorization in FactorialExtend.lean and separately checked both paths to the same actual packed 106000! value. Each printed only propext and Quot.sound. With matched imports and the two methods in reversed run order, full-product checks took 24.97 and 23.67 CPU seconds. Incremental checks took 17.95 and 17.34 CPU seconds. This saves 7.02 and 6.33 CPU seconds per fresh process, respectively. The import-only controls cost 17.89 and 15.11 seconds. Few seconds of residual difference after subtracting imports are sensitive to run-to-run noise; this small measured saving applies to the common factorial check, once each time the cutoff changes. Reusing an unchanged common table across additional bands avoids that new admission entirely while the row bounds hold.
